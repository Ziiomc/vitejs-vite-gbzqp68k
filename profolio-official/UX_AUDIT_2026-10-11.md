# ProFolio — UI/UX visual audit · 2026-10-11

## Intent
US-English-first real-estate exploration demo, with one recognizable wine-and-gold design system. Do not misrepresent demo homes as purchasable properties, local profiles as real logins, or planned Pro features as billed subscriptions. Spanish remains optional.

## Evidence and findings
Reviewed the user-provided desktop captures (approximately 1,525 px wide), `index.html`, `premium.css`, `amen-experience.css`, `etapa0-mapa.css`, `map-fix-v4.js`, `amen-experience-v2.js`, and the existing launch, Open Tour and localization scripts.

| Finding | Root cause | Fix |
| --- | --- | --- |
| **Duplicate Regular/Premium/Opportunity/Turbo buttons** | `map-fix-v4.js` creates `#filters` and `amen-experience-v2.js` injects a second interactive `#amenMapKey`. | Remove the redundant injected quick-filter bar. Keep the original category filters. Retain descriptive symbols under the native `Map symbols` disclosure. |
| **Mobile navigation fails on some clicks** | Calling `.forEach` on the single-element selector `$('#amenBottomNav button')`. | Use the list selector `$$` to update all six button states. |
| **Neighborhood tags obscure the map at regional zoom** | All area labels render simultaneously regardless of zoom. | Hide area labels under zoom 11, reveal at focused zoom; area selector continues to work at every zoom. |
| **Tiny card type and actions** | Competing CSS declarations force 7–11px labels on cards. | Consolidated typography, ~20px prices / 14px titles, readable metadata, 40px controls; phone-specific scaling. |
| **Crowded filters and redundant visual weight** | Three legacy theme files compete to style the toolbar. | Add a single last-loaded `ux-consolidation.css` with controlled toolbar/filters and responsive breakpoints. |
| **Desktop sidebar can conceal lower navigation links** | Non-scrolling nav sits above a large upgrade card. | Scrollable sidebar navigation with a bounded footer. |
| **Unnecessary floating bottom bar on desktop** | Mobile quick-nav is injected on all viewports and hidden only by newer CSS. | Explicitly hidden above 980px; available on mobile with legible labels/touch targets. |
| **Map legend hidden on mobile** | Multiple mobile media rules turn it off. | Accessible compact `Map symbols` disclosure on phones; no second filter row. |
| **Local profile resembles a real online account** | `MY ACCOUNT` heading with no storage caveat. | Explicit local-only profile notice, no online login or agent contact claims; safe sound-settings writes. |

## Layout rules to protect
- Wide desktop, ≥1280px: full sidebar; floating featured homes on right; map remains primary.
- Laptop, 981–1279px: featured homes below map in readable grid; no forced overlap.
- Tablet/mobile, ≤980px: six-target bottom navigation, no sidebar obstruction; horizontally scrollable listing carousel.
- Small mobile, ≤700px: two-column primary control grid, readable selects (16px), touch targets at least roughly 40px.
- Narrow mobile, ≤390px: single-column secondary filters; avoid viewport-wide overflow.
- Reduced motion and dark mode: preserve keyboard focus and text contrast.

## Tests and open verification
Automated connector-side checks: JavaScript syntax, HTML id uniqueness, CSS brace matching, responsive selector rules, expected ten illustrative samples, category totals, filter updates, Open Tour open/close, active state switching across mobile navigation, marker density toggles. Vercel deployment builds must complete and the public original domain must resolve to the intended commit.

**Limit:** screenshot-driven CSS review and mock-DOM tests do not replace real-device visual QA. Verify the live app in a browser at 1525, 1366, 1024, 390, 375 and 320 CSS pixels before calling the experience production-validated; inspect horizontal scroll, property carousel, filter categories, modal sizes, focus, saved tours and local draft import/export. Any further issue should be patched on the same Vercel project.

No new databases or projects were created. Actual agent accounts, leads, verified listings, payment, and production persistence remain unimplemented.
